# Y:ON Frontend — AGENTS.md

이 문서는 `frontend/` 작업에 적용한다. 저장소 루트의 `AGENTS.md`와 `README.md`도 함께 따른다. 규칙이 충돌하면 작업을 임의로 진행하지 않고 충돌 내용을 보고한다.

## 1. 작업 범위 및 권한

- **파일 생성·수정·삭제는 반드시 `frontend/` 내부에서만 수행한다.** 저장소 루트와 `backend/`, `data-service/`, `notification-service/`, `contracts/`, `docs/`, `docker/`, `deploy/` 등 다른 경로는 수정하지 않는다.
- **다른 경로의 파일을 읽거나 검색하는 것은 허용한다.** 특히 백엔드 Controller, DTO, Security 설정, API 계약 및 테스트를 직접 확인한다.
- 외부 경로의 수정이 필요하면 이유와 대상 파일을 보고한다. 대신 수정하거나 우회하지 않는다.
- **Git 변경 작업은 사용자가 직접 수행한다.** Codex는 `git add`, `commit`, `push`, 브랜치 생성·전환·병합·삭제, `reset`, `rebase`, `stash`, 태그 또는 PR 생성·수정을 실행하지 않는다. `git status`, `log`, `diff`, `show` 등 조회만 허용한다.
- 사용자가 요청하지 않은 배포, 의존성 일괄 업데이트, 대규모 리팩터링을 수행하지 않는다.

## 2. 사실 확인 및 API 계약

- 작업 전에 최신 실제 파일과 관련 코드를 확인한다. 문서보다 구현이 다르면 차이를 알리고 임의로 계약을 확정하지 않는다.
- `frontend/`에 아직 없는 라이브러리·컴포넌트·라우트·에셋을 존재하는 것으로 가정하지 않는다.
- API 경로, HTTP 메서드, 파라미터, 요청·응답 필드, 인증 요구사항은 실제 백엔드 코드와 계약으로 검증한다. 추측한 데이터를 실제 기능으로 구현하지 않는다.
- 인증 쿠키, CSRF, 공통 오류 응답 및 권한별 노출을 백엔드 계약에 맞게 처리한다. 인증을 임의로 우회하지 않는다.
- API가 지원하지 않는 필터·정렬·상태·수치·메뉴를 임의로 추가하지 않는다. 알림의 미완료 기능을 완료된 것처럼 표시하지 않는다.
- 테스트·미리보기용 데이터는 명시적으로 분리하고 운영 데이터처럼 표시하지 않는다.

## 3. 서비스 도메인

- Y:ON은 **청년정책·직업훈련 통합 탐색, 신청 가능성 판정, 개인화 추천, 저장·숨김, 변경 추적·알림** 서비스다.
- 비로그인 사용자는 공개 검색과 상세 조회를 사용할 수 있다. 개인화 기능의 인증 조건은 실제 API에 따른다.
- 신청 가능성(`ELIGIBLE`, `POSSIBLY_ELIGIBLE`, `NOT_ELIGIBLE`, `UNKNOWN`)과 현재 모집 상태는 별개다. 불확실한 판정을 확정 표현하지 않는다.
- 청년정책의 **신청기간**과 직업훈련의 **교육기간·교육 시작일**을 혼동하지 않는다.
- 저장과 숨김은 서로 다른 기능이다. 추천 결과가 비어 있다는 이유로 기회 자체가 없다고 단정하지 않는다.

## 4. 브랜드 및 UI/UX

- 기본 화면은 **매우 밝은 회백·아이보리 배경 위에 흰색 카드·박스를 분리해 배치**한다. 저채도 세이지 그린을 주요 포인트로 사용하고, 연두·연노랑은 제한적으로 활용한다.
- 기존에 확정된 Y:ON 전구·새싹 로고 에셋을 우선 사용한다. 에셋이 없으면 위치를 확인하고 요청한다. 임의로 새 로고를 만들지 않는다.
- **금지:** 그라데이션 배경·버튼, AI 생성형 랜딩페이지 특유의 발광·네온, 글래스모피즘, 과도한 그림자·블러, 3D 장식, 실사·스톡·인물 이미지, 공고 임의 썸네일, 의미 없는 그래프와 장식.
- 정보 위계는 여백, 타이포그래피, 얇은 경계선, 절제된 배경색으로 표현한다. 색상·간격·폰트는 공통 디자인 토큰을 재사용한다.
- 홈은 기회 발견 중심의 카드형 구성을, 검색은 좌측 필터와 목록형 결과 구성을 우선한다. 개별 화면의 상세 구조는 실제 요구사항을 확인한다.
- 확정되지 않은 비교·커뮤니티·신청 현황 등의 기능을 시안에서 가져와 추가하지 않는다.

## 5. 반응형 및 접근성

- **데스크톱과 모바일 모두 필수 지원 대상**이다. 각 화면 구현 시 두 환경을 함께 확인한다.
- 좁은 화면에서는 그리드를 재배치하고 검색 필터를 별도 패널로 제공한다. 불필요한 가로 스크롤과 긴 한글 텍스트 잘림을 방지한다.
- 키보드·포커스·레이블·터치 영역·명도 대비를 고려한다. 상태 정보는 색상 외에 텍스트로도 제공한다.
- 로딩, 빈 결과, 오류, 인증 필요 및 데이터 미확인 상태를 실제 동작에 맞게 구분한다.

## 6. 코드 및 검증

- 기존 구조, 프로젝트 설정, 린트·네이밍 규칙을 우선한다. 추가 라이브러리는 필요성을 확인하고 최소한으로 도입한다.
- UI 컴포넌트에 HTTP 요청, 인증 처리, 복잡한 비즈니스 로직을 직접 섞지 않는다.
- 실제로 재사용되는 요소만 공통 컴포넌트로 분리한다. 불필요한 Repository·인터페이스·계층을 만들지 않는다(YAGNI).
- 비밀키·토큰·운영 설정값을 코드에 하드코딩하지 않는다.
- 작업 후 변경한 범위에 맞춰 타입 검사·린트·테스트·빌드를 실행하고, 실행하지 못한 검증과 이유를 명시한다.
- 결과 보고에는 수정한 `frontend/` 파일, 주요 변경, 검증 결과, 남은 문제만 간결히 기록한다. **커밋·푸시는 사용자가 수행하도록 남긴다.**
