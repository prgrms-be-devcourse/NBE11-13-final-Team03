# 고용24 수집 실패 처리와 정합성 범위

- 같은 페이지는 재시도 가능한 오류에만 최초 요청 포함 최대 3회 요청한다.
- 첫 페이지 실패 시 해당 NCS를 미완료 처리하고 다음 NCS로 이동한다.
- 중간 페이지 실패 시 실패 요청 조건과 오류를 기록하고 다음 페이지를 수집한다. 재시도 불가 오류도 인증 오류가 아니라면 동일하게 처리한다.
- HTTP 401·403은 어느 페이지에서 발생하든 전체 수집을 중단하고 현재 및 남은 NCS를 미완료 처리한다.
- 페이지 상한에 도달해도 마지막 페이지임을 확인하지 못하면 해당 NCS는 미완료다.

`completed`는 모든 NCS의 페이지 순회 완료 여부다. 실패한 중간·마지막 페이지가 있어도 순회는 완료될 수 있으므로, 전체 조회 성공 여부는 `pageFailures`도 함께 확인해야 한다.

## 페이지 재시도로 해결되지 않는 문제

조회 날짜 범위와 정렬 조건은 실행 동안 고정하지만 외부 목록은 고정된 스냅샷이 아니다. 신규 등록·수정·삭제로 페이지 경계가 이동하면 중복 또는 누락이 생길 수 있다. 전체 건수가 같아도 목록이 바뀔 수 있고, 실패한 페이지를 나중에 재조회해도 처음 실패한 항목과 같은 항목이 반환된다고 보장할 수 없다. `completed=true`와 실패 목록이 비어 있는 경우에도 무누락을 의미하지 않는다.

수동 최신화는 수집 서비스의 `collectPages`를 사용한다. 페이지 하나를 조회할 때마다 처리기를 호출해 항목별 원본·정제 요청 저장을 마친 뒤 다음 페이지로 진행한다. 같은 외부 항목을 수집 목록에서 임의로 제거하지 않으며, 출처·외부 식별자를 기준으로 직전 원본과 비교한다. 기존 `collect` 메서드는 이 순회 위에서 전체 목록을 모아 반환하는 호환 경로로 유지한다.

주기적 전체 수집·재대조로 일시적인 누락을 보완하고, 단일 실행에서 보이지 않았다는 이유만으로 삭제·마감을 확정하지 않는다. 스냅샷 또는 커서가 없는 페이지 API의 한계는 재시도만으로 제거되지 않는다. `collectPages`는 페이지 조회·순회만 담당하고, 실제 비교·저장은 Worker가 연결한 처리기와 RawRecordService가 담당한다. 자동 재대조 작업은 아직 없다.

## 원본 저장 서비스

`RawRecordService.save`는 이미 생성된 RUNNING 수집 실행과 `RawRecordSaveRequest`를 받아 항목 하나를 저장한다. API 호출과 분리된 트랜잭션이며, 실행 행과 출처 행을 순서대로 잠근 후 해당 출처·외부 ID의 마지막 삽입 스냅샷과 비교한다. 최초 삽입 경합도 출처 행 잠금으로 직렬화한다. 이 잠금 규약을 거치지 않는 직접 원본 INSERT는 지원하지 않는다.

- 직전 해시가 같으면 기존 스냅샷의 `lastSeenAt`만 갱신한다. `sync_id`와 최초 관측 시각은 유지한다.
- 신규 또는 직전 해시가 다르면 새 스냅샷을 저장한다. A→B→A도 세 스냅샷으로 남는다.
- 실행 시작 시각 또는 직전 `lastSeenAt`보다 이른 관측 요청은 거부한다. DB 오류는 호출자에게 전파해 트랜잭션을 롤백한다.
- 출처는 수집 실행에서 결정한다. 외부 ID와 비교 해시는 호출자가 출처별 식별·해시 규칙에 따라 제공해야 한다. 서비스는 JSON을 정규화하거나 해시를 다시 계산하지 않는다.

관측 시각만으로 외부 데이터의 실제 최신성을 증명할 수는 없다. [수동 최신화 API](manual-sync-api.md)는 출처별 실행 중첩을 방지하고 페이지마다 원본·정제 요청·성공 건수를 항목별 트랜잭션으로 커밋한다. 정제 요청 저장 실패도 원본과 함께 롤백한다. 신뢰 가능한 외부 수정 버전 검사와 항목별 성공 관측 이력은 아직 없다.

관리자 원본 저장·조회 API와 실제 PostgreSQL의 JSONB 매핑, 최초 삽입 경합, DB 제약 위반 롤백은 컨트롤러 통합 테스트로 검증한다. 실행 방법과 HTTP 계약은 [collection-api.md](collection-api.md)를 참고한다.
